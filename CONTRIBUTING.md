# Contributing to NetShare Player

Thank you for your interest in improving NetShare Player.

We welcome bug reports, feature suggestions, documentation improvements,
translations, testing feedback, and authorized code contributions.

## Before Contributing Code

The current NetShare Player license requires prior written authorization
before modifying or creating derivative works from the project.

Before starting a code contribution, please:

1. Open a GitHub issue describing the proposed change.
2. Explain the problem, expected behavior, and suggested solution.
3. Wait for written approval from a project maintainer.
4. Reference the approved issue in your pull request.

You may also request authorization by contacting
[contact@netshareplayer.com](mailto:contact@netshareplayer.com).

## Reporting Bugs

Before opening a bug report:

- Check that the issue has not already been reported.
- Test with the latest available release.
- Remove passwords, access tokens, private URLs, personal files, and other
  sensitive information from logs or screenshots.

Please include:

- NetShare Player or NetShare Server version
- Operating system and version
- Steps to reproduce the problem
- Expected behavior
- Actual behavior
- Relevant logs or screenshots
- Whether the connection is local or remote

## Suggesting Features

Feature requests should explain:

- The problem or use case
- The proposed behavior
- Who would benefit from it
- Any privacy, security, accessibility, or compatibility considerations

## Translations

Translation improvements are welcome.

Please include:

- The language and locale
- The affected interface text
- The proposed translation
- Context for terms that may have multiple meanings

Keep placeholders, formatting markers, and application terminology intact.

## Pull Requests

After receiving authorization:

1. Fork the repository.
2. Create a focused branch for the change.
3. Keep the implementation limited to the approved issue.
4. Follow the existing project structure and coding style.
5. Do not commit credentials, certificates, private keys, build secrets,
   personal information, or generated release artifacts.
6. Update the relevant English documentation when behavior changes.
7. Test the affected platforms and describe the validation performed.
8. Open a pull request referencing the approved issue.

A pull request should contain:

- A clear title and summary
- The related issue number
- The reason for the change
- Testing and validation results
- Screenshots for visible interface changes
- Compatibility or migration notes when applicable

Submitting a pull request does not guarantee that it will be accepted.

## Scope and Design

Contributions should preserve NetShare Player's core principles:

- Local-first operation
- User privacy and control
- Secure access
- Cross-platform compatibility
- Accessibility
- Clear and maintainable interfaces

Large architectural changes should be discussed with the maintainers before
implementation begins.

## Security Reports

Do not publicly disclose vulnerabilities that could expose user data,
credentials, private files, or remote-access endpoints.

Please report security concerns privately to
[contact@netshareplayer.com](mailto:contact@netshareplayer.com).

Include only the information required to reproduce and understand the issue.

## Documentation

Documentation contributions should:

- Be written in clear English
- Describe current public behavior
- Avoid internal planning notes or implementation roadmaps
- Avoid publishing secrets, private infrastructure details, or signing data
- Update related links and examples when necessary
